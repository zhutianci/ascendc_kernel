# 性能测试结果

昇腾 910B4 · CANN 9.1.0 · 官方 `auto_bench.py`（warmup=200 + repeat=500 取中位，
wall-clock 含 host 开销，`--seed 42`）。

## 一、三算子成绩

| 算子 | v0 参考 (ms) | v1 本作品 (ms) | **加速比** |
|---|---|---|---|
| Task1 SparseAttention | 12.81 – 12.83 | **1.039 – 1.052** | **12.18 – 12.35 ×** |
| Task2 Lightning Indexer | 9.31 – 9.33 | **1.232 – 1.246** | **7.49 – 7.57 ×** |
| Task3 Sinkhorn (mHC) | 1.59 – 1.68 | **0.102 – 0.105** | **15.6 – 16.1 ×** |

三个算子在评测输入上均与参考实现**逐位相同**（不是"在容差内"）：

```

E128_GATE   GREEN      Task2 int64 逐位门（torch.equal，含 8 次计时形态直调）
E120_GATE   GREEN      Task3 逐位门  maxabs = 0.000e+00
E121_GATE   GREEN      Task1 逐位门  maxabs = 0.000e+00
sim_verify  12/12 PASS CPU 语义仿真器
harness_dryrun  PASS   评测器 AST 过滤器兼容性自检
```

## 二、提交版 vs 开发版的等价性验证

提交版是从开发版重构出来的（删除不可达代码、改写注释）。为确认重构没有改变行为，
两者在**同一会话内交错**跑了 3 轮官方评测（µs 级差异下单跑排名不可信，必须交错配对）：

v1 耗时（ms）：

| 轮次 | T1 开发版 | T1 提交版 | T2 开发版 | T2 提交版 | T3 开发版 | T3 提交版 |
|---|---|---|---|---|---|---|
| 1 | 1.0381 | 1.0517 | 1.1882 | 1.2324 | 0.10952 | 0.10545 |
| 2 | 1.0417 | 1.0392 | 1.2346 | 1.2409 | 0.09648 | 0.10481 |
| 3 | 1.0579 | 1.0394 | 1.2387 | 1.2457 | 0.10325 | 0.10166 |
| **中位** | **1.0417** | **1.0394** | **1.2346** | **1.2409** | **0.10325** | **0.10481** |
| Δ | — | **−2 µs** | — | **+6 µs** | — | **+1.6 µs** |

三项差异都落在各自的测量抖动带内（T2 的基线漂移带实测为 ±11 µs），
且四道逐位门在提交版上全绿 ⇒ **重构是行为中性的**。

四个 kernel 源码另外经过 token 级比对：剥掉注释与空白后与开发版**逐 token 相同**
（1503 / 1758 / 498 / 951 tokens），即重构只动了注释和不可达代码，没有碰任何一条指令。

## 三、距离物理下限

用消融（把某一段改成空操作再量墙差）而不是计数器均值来定墙。

**Task1** — q 读 340.8MB + out 写 340.8MB 由 I/O 规格钉死。HBM 读写共用总线不能并发，
所以下界是"读时间 + 写时间"的加性和：

```
863.2 µs  20 核硬件加性地板（自研 AIV 流式 kernel 标定：读 828 / 写 803 GB/s）
+ 43.1    S/P 的 L2 往返（cube→UB 在 A2 训练卡上不存在，架构级不可避免）
+ 41.0    mm1↔mm2 交替（要拿它必须放开缓冲相位数，一放开就撞 L2 墙）
+ 37.0    AIV 干扰
− 26.0    跨 launch 钉住一批 q 在 L2
```

**Task2** — `ix_fused` 约 978 µs，AIC-only 地板 655 µs，AIV 侧余量 323 µs：

| 桶 | µs | 占比 | 状态 |
|---|---|---|---|
| bf16 舍入链（4 条全宽 fp32 通道） | 122 | 38% | **ISA 强制**：`Mul` 的 `SupportType` 无 bf16 |
| 选择级联（Sort32 + MrgSort 树） | 72 | 22% | k/n = 128/672 ≈ 19%，剪枝类算法无效 |
| 残差（S 的 DataCopy + Add 树 + 输出 + flag） | 129 | 40% | ≈ `aiv_mte2`，**MTE2 才是真实地板** |

把 AIV 侧算术几乎全部拿掉，`ix_fused` 仍有 784 µs。

**Task3** — v1 约 103 µs 里我们能碰的只有约 22 µs（host 10 + kernel 12），
其余是评测框架的 `sync_devices`（40 µs）与 `set_seed` 设备残留（36 µs），
且都发生在 `forward` 返回**之后**，v0/v1 同样背负。

## 四、复现方式

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
python3 tools/audit.py          # 静态自检
bash run_benchmark.sh 3         # 三轮官方评测
```

首次运行每个算子的 `__init__` 会 JIT 编译 kernel（约 1-2 分钟），
产物按源码哈希缓存；**编译在 `__init__` 内，不计入计时区间**。
